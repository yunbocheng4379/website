# Docker 生产部署设计

## 目标

为现有 React、TypeScript、Vite 单页应用提供可重复执行的 Docker 生产部署方式，并提供面向服务器运维的中文操作文档。

部署完成后，应用由 Nginx 提供静态资源服务，默认通过服务器的 `8080` 端口访问。页面中指向“笔记生花”的链接默认使用当前访问页面的服务器主机名和 `3015` 端口，并允许在构建镜像时覆盖为完整 URL。

## 架构

采用多阶段镜像构建：

1. Node.js 构建阶段通过 `npm ci` 安装锁定版本依赖，并运行 `npm run build` 生成 `dist`。
2. Nginx 运行阶段仅复制 `dist` 和站点配置，不携带 Node.js、源码或开发依赖。
3. Docker Compose 负责镜像构建、端口映射、自动重启和健康检查。

## 文件与职责

- `Dockerfile`：定义 Node.js 构建阶段和 Nginx 运行阶段。
- `nginx.conf`：提供静态文件服务、单页应用路由回退、缓存、压缩和健康检查端点。
- `docker-compose.yml`：声明应用服务、构建参数、端口、健康检查和重启策略。
- `.dockerignore`：排除依赖目录、构建产物、版本控制及本地配置。
- `.env.example`：展示服务器对外端口、关联应用端口及可选完整 URL 配置。
- `DEPLOYMENT.md`：记录服务器准备、上传代码、配置、启动、验证、更新、日志、停止、回滚和故障排查流程。

## 关联应用地址

前端读取可选构建变量 `VITE_NOTE_APP_URL`：

- 已设置时，直接使用该完整 URL，适合域名、HTTPS 或反向代理场景。
- 未设置时，在浏览器中根据当前页面协议和主机名生成地址，并使用 `VITE_NOTE_APP_PORT` 指定的端口；端口默认是 `3015`。

该逻辑避免把 `localhost` 发送给访问者，也避免服务器 IP 变更时必须修改源码。若主站使用 HTTPS，而关联应用仅提供 HTTP，部署人员应通过 HTTPS 域名或反向代理设置 `VITE_NOTE_APP_URL`，避免浏览器安全限制。

## 服务行为

- 容器内 Nginx 监听 HTTP 端口。
- 宿主机默认将 `8080` 映射到容器服务端口，可通过 `.env` 修改。
- `/health` 返回成功状态，供 Docker 健康检查使用。
- 不存在的静态路径回退到 `index.html`，支持未来添加客户端路由。
- 带内容哈希的静态资源使用长期缓存，HTML 不使用长期缓存，确保更新能及时生效。
- 容器配置自动重启，服务器或 Docker 重启后可自行恢复。

## 错误处理与运维

- 依赖安装或前端构建失败时，镜像构建直接失败，不产生不完整镜像。
- Nginx 健康检查失败时，容器状态显示为 `unhealthy`，通过 Compose 日志定位问题。
- 部署文档提供端口占用、防火墙、关联服务不可访问、HTTPS 混合内容和构建失败的排查方法。
- 更新采用重新构建并启动容器的流程；文档同时说明基于旧镜像标签的手动回滚思路。

## 验证标准

1. `npm run lint` 成功。
2. `npm run build` 成功。
3. `docker compose config` 能正确解析配置。
4. `docker build` 成功。
5. 容器启动后 `/health` 返回 HTTP 200，首页返回 HTML。
6. 生成的前端资源中不再包含 `http://localhost:3015/`。
7. 部署文档中的文件名、变量名、端口和实际配置一致。

## 范围限制

- 本次不配置域名、TLS 证书、云厂商安全组或宿主机反向代理，因为这些依赖具体服务器环境。
- 本次不将远程视频和字体资源打包到镜像；运行时仍需访问现有外部资源。
- 本次不负责部署 `3015` 端口对应的关联应用，只确保当前页面生成正确的服务器地址。
